# io: Reader, Writer, files

A surprising amount of Go — networking, files, HTTP, strings — is about
moving bytes. The whole standard library is held together by two tiny
interfaces:

```go
type Reader interface {
	Read(p []byte) (n int, err error)
}

type Writer interface {
	Write(p []byte) (n int, err error)
}
```

> [!key]
> **An `io.Reader` is anything you can read bytes from. An `io.Writer` is
> anything you can write bytes to.** Once you understand these two contracts,
> thousands of stdlib types become interchangeable pieces of a pipeline.

## The Reader contract

`Read(p []byte)` fills the buffer `p` and returns how many bytes were read,
plus an `error`. When there is nothing left, it returns `io.EOF`. Important
subtleties:

- It may return `0 < n` **and** a non-nil error at the end of data (like EOF).
- You must always check `n` before using the data — err on its own isn't enough.

The classic full-read pattern looks like this:

```go
import (
	"fmt"
	"io"
	"strings"
)

r := strings.NewReader("hello io")
buf := make([]byte, 3)
for {
	n, err := r.Read(buf)
	if n > 0 {
		fmt.Printf("read %d bytes: %q\n", n, buf[:n])
	}
	if err == io.EOF {
		break
	}
	if err != nil {
		fmt.Println("other error:", err)
		break
	}
}
```

## strings.NewReader: data as a stream

`strings.NewReader(s)` wraps a string in an `io.Reader` — the cheapest way to
get streaming semantics over data you already have in memory. It is the
recommended stand-in for a real file when you want to test or demo file-like
code (and it's what the runner uses for everything here).

```go
import (
	"bytes"
	"fmt"
	"io"
	"strings"
)

r := strings.NewReader("ABCDEF")
var buf bytes.Buffer
n, err := io.Copy(&buf, r)
fmt.Println("copied", n, "bytes; err =", err)
fmt.Println("content:", buf.String())

// rewind by making a fresh reader
again := strings.NewReader("ABCDEF")
head := make([]byte, 2)
again.Read(head)
fmt.Println("first two:", string(head))
```

## io.Copy: the plumbing tool

`io.Copy(dst io.Writer, src io.Reader)` copies everything from a reader to a
writer, returning the byte count. It is the idiomatic bulk transfer used
everywhere — files to network, strings to buffers, buffers to files.

```go
import (
	"bytes"
	"fmt"
	"io"
	"strings"
)

src := strings.NewReader("streaming text")
var dst bytes.Buffer

n, err := io.Copy(&dst, src)
fmt.Println("copied:", n, "bytes, err:", err)
fmt.Println("buffer now:", dst.String())
```

> [!tip]
> `bytes.Buffer` implements `io.Writer` (via `Write`) *and* `io.Reader` (via
> `Read`), making it a perfect in-memory destination and source for
> `io.Copy` pipelines.

## Files: os.ReadFile and os.WriteFile

In a real program, the reader and writer are files opened with `os.Open` /
`os.Create`. Go also provides two one-shot helpers that handle the common
"read the whole file / write the whole file" cases in a single call:

- `os.ReadFile(name)` → `([]byte, error)`
- `os.WriteFile(name, data, perm)` → `error`

The full-open pattern also exists (`os.Open`, `os.Create`) when you need
sequential scanning, but the helpers cover 90% of file work.

```go eval=no
import (
	"fmt"
	"os"
)

func main() {
	err := os.WriteFile("/tmp/notes.txt", []byte("study Go daily\n"), 0o644)
	if err != nil {
		fmt.Println("write error:", err)
		return
	}
	data, err := os.ReadFile("/tmp/notes.txt")
	if err != nil {
		fmt.Println("read error:", err)
		return
	}
	fmt.Printf("file contained %d bytes: %q\n", len(data), data)
}
```

> [!note] Why this block is `eval=no`
> It writes to a real filesystem path and hits the OS layer; the on-device
> interpreter keeps you sandboxed. The exact same logic runs against
> `strings.NewReader` / `bytes.Buffer` in the runnable examples — the stream
> plumbing is identical, only the endpoint differs.

## Buffered reading

Real-world scanning (lines, tokens) is done with buffered readers from
`bufio`, which wrap any `io.Reader`. The pattern is: reader over lines →
iterate with `Scan`.

```go
import (
	"bufio"
	"fmt"
	"strings"
)

src := "one\ntwo\nthree\n"
scanner := bufio.NewScanner(strings.NewReader(src))
for scanner.Scan() {
	fmt.Println("line:", scanner.Text())
}
if err := scanner.Err(); err != nil {
	fmt.Println("scan error:", err)
}
```

> [!warning]
> `for scanner.Scan()` is a loop, not an `if`! `Scan` returns true while a
> line is available. A common bug is checking it once and wondering why only
> the first line prints.
